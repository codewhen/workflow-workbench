# Storage, backups and portability

Workbench uses local YAML and JSON files, not a hosted database. There are two locations to understand: your **project directory** and the **library/run storage directory**.

## Project files

A project contains workflow YAML, companion scripts, child workflows and files used/generated by operations. The optional `workspace` field selects an execution root relative to the YAML directory; it defaults to `.`. Operation paths resolve within that root. Each child workflow resolves its own workspace.

`workbench create` saves a blank YAML in the terminal's current directory. Registering a project references its files in place. Open YAML registers the original file in place, preserving relative dependency paths. Import a copy saves browser-uploaded contents into a newly chosen destination file. Home's organization folders normally change only library metadata.

## Library and evidence

The current default is `~/.workbench-preview-v3`, independent of which project directory you open. Choose a permanent custom path with:

```bash
workbench serve --storage ~/Documents/WorkbenchLibrary
```

```text
library.json                  registered project paths, entry IDs, nested folder paths
browser-sessions.json         protected local request/session tokens
drafts/                       submitted, revision-matched recovery backups
projects/starter/             separate Starter YAML files
runs/RUN_ID/summary.json       status, typed results, fingerprint and attempts
runs/RUN_ID/events.jsonl       execution event trail
runs/RUN_ID/report.html        saved human-readable report
runs/RUN_ID/*.log              execution logs
runs/RUN_ID/children/          child workflow evidence
```

Some development dashboards explicitly use `/private/tmp` storage. That is temporary development data, not the normal permanent CLI default. Use the actual serving command/printed path; do not assume a dashboard on port 3105 uses the default.

The npm launcher's Python environment cache is separate from this storage. Uninstalling an npm launcher does not intentionally delete your projects or reports. Do not delete an active runtime cache while it serves work.

## Back up and move storage

1. Save browser drafts and stop the serving terminal after work is idle.
2. Copy the entire storage directory to a permanent backup, preserving browser-sessions.json privately.
3. Back up project directories separately, including YAML, scripts and required local files. The library references absolute project paths; it is not a copy of their contents.
4. Start Workbench with `--storage` pointing at the copied storage and the correct project directory.
5. Open Home, refresh and verify projects/reports before removing the old copy.

Moving storage does not relocate the referenced projects automatically. Moving projects to a different machine changes paths; re-register their new locations and treat resume as a deliberate compatibility check. Do not assume successful evidence can be reused after changing a workspace's identity.

## Drafts and privacy

Server draft backups are made for submitted drafts and matched to the saved base revision. They are not continuous browser autosave. Save before closing, rebuilding or restarting. Session tokens are local protection data; do not commit or share them. Masked run logs can still include nonsecret paths/project details: review reports before sharing.

See [Home and projects](projects.md) and [running/resume](running.md) before reorganizing work with active runs.
